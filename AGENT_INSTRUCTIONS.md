1. CORE ARCHITECTURAL PRINCIPLES & NON-NEGOTIABLES
--------------------------------------------------------------------------------
1. Production-Grade Quality:
    - No mock stubs, no pseudo-code, and no `// TODO: implement later` in core business logic.

2. Zero-Leakage Hierarchical Multi-Tenancy:
    - Data hierarchy: User -> Organization -> Workspace -> Documents -> Chunks (pgvector).
    - Absolute tenant isolation: Every SQL query and vector similarity search MUST be explicitly scoped by `organization_id` and `workspace_id`.
    - Authorization must be enforced strictly on the backend via centralized evaluators, never solely on the client.
3. Provider-Agnostic AI Architecture:
    - All AI integrations MUST live behind domain interfaces (`EmbeddingService`, `AiChatService`).
    - The business layer must NEVER import Google Gemini SDK classes directly.
    - Gemini is the primary provider for MVP, but the abstraction must allow plugging in other LLM providers without rewriting business logic.
4. Anti-Hallucination & Verified Citations:
    - The system prompt must enforce strict adherence to retrieved context. The AI must never extrapolate or invent facts, procedures, or dates.
    - If retrieved context is insufficient, the system must deterministically return:
      "I couldn't find enough information in the organization's knowledge base to answer this question."
    - Citations are structured metadata (Document ID, Document Name, Page Number, Chunk ID, Quote Snippet), NOT raw text blended into the answer. Citations generated by the AI must be validated against the actual retrieved chunks before returning them to the user.

5. RAG PIPELINE & AI INTEGRATION SPECIFICATIONS
--------------------------------------------------------------------------------
A. Document Processing Flow:
1. User uploads PDF to `POST /api/v1/workspaces/{workspaceId}/documents`.
2. Validate MIME type (`application/pdf`) and size limit. Store file via `FileStorageService`.
3. Create document record with status `UPLOADED`.
4. Dispatch asynchronous processing job (`@Async`).
5. Worker updates status to `PROCESSING`, extracts text per page using Apache PDFBox.
6. Split text with deterministic chunker (configurable chunk size ~500-1000 characters, overlap ~100 characters), retaining `pageNumber` and `chunkIndex`.
7. Generate embeddings in batches via `EmbeddingService` (`gemini-embedding-2`).
8. Save chunks with embeddings into `document_chunks` table and update status to `READY`.
9. On exception: update status to `FAILED` with descriptive `errorMessage`.
   B. Query & RAG Retrieval Flow:
1. User sends message to `POST /api/v1/conversations/{id}/messages`.
2. Generate query vector using `EmbeddingService`.
3. Execute similarity query in PostgreSQL using cosine distance:
   `SELECT ... 1 - (embedding <=> :queryVector) AS similarity FROM document_chunks WHERE organization_id = :orgId AND workspace_id = :workspaceId ORDER BY similarity DESC LIMIT :topK`
4. Filter results with minimum similarity threshold (e.g., >= 0.65).
5. If no chunks pass threshold: Return response with `insufficientInformation = true` and standard fallback answer.
6. If chunks retrieved: Construct prompt with numbered context snippets and chunk identifiers.
7. Query `AiChatService` using Gemini structured output enforcing JSON schema:
   ```json
   {
     "answer": "string",
     "citations": [
       { "chunkId": "string", "documentName": "string", "page": 1, "quoteSnippet": "string" }
     ],
     "insufficientInformation": false
   }
   ```
8. Verify AI citations against the physically retrieved chunks. Discard any hallucinated citation IDs.
9. Persist message and citations in a single database transaction. Return response to user.
